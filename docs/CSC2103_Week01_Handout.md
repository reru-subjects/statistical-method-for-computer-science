## ส่วนที่ 2: บทนำ — ทำไมต้องสรุปข้อมูลก่อนทำอย่างอื่น

ลองนึกภาพว่าคุณเป็นผู้ดูแลระบบลงทะเบียนเรียนออนไลน์ของมหาวิทยาลัย ในช่วงเปิดลงทะเบียน ระบบมีคำขอ (request) นับแสนรายการต่อวัน หัวหน้าถามว่า "ระบบตอบสนองเร็วแค่ไหน" คำตอบที่ดีไม่ใช่การส่งไฟล์ log 100,000 บรรทัดให้ดู และไม่ใช่การตอบสั้น ๆ ว่า "ประมาณ 140 มิลลิวินาที" โดยไม่บอกว่าตัวเลขนั้นมาจากอะไร

**สถิติเชิงพรรณนา (Descriptive Statistics)** คือชุดเครื่องมือที่ช่วย "ย่อ" ข้อมูลจำนวนมากให้เหลือตัวเลขและกราฟไม่กี่ตัว โดยยังรักษาข้อมูลสำคัญไว้ ในสัปดาห์นี้เราตอบคำถามสามข้อ

1. ข้อมูลที่เรามีเป็นข้อมูลชนิดใด และมาจากไหน (ประชากร หรือตัวอย่าง)
2. ตัวเลขใดอธิบาย "ค่ากลาง" และตัวเลขใดอธิบาย "การกระจาย"
3. ถ้ามีค่าที่ผิดปกติมาก ๆ ปนอยู่ จะรายงานอย่างไรให้ซื่อสัตย์และไม่ทำให้ผู้อ่านเข้าใจผิด

### ตัวอย่างเดินเรื่องตลอดบท: ระบบลงทะเบียนเรียนออนไลน์ "RegisRERU"

## ส่วนที่ 3: ประชากร ตัวอย่าง และชนิดของข้อมูล

### 3.1 ประชากรและตัวอย่าง

| คำศัพท์ | ความหมาย | ตัวอย่างใน RegisRERU |
|---|---|---|
| ประชากร (Population) | กลุ่มทั้งหมดที่เราต้องการศึกษา | คำขอทั้งหมดของระบบตลอดวัน |
| ตัวอย่าง (Sample) | ส่วนของประชากรที่เก็บมาวิเคราะห์จริง | คำขอ 20 รายการที่ log เก็บไว้ |
| พารามิเตอร์ (Parameter) | ค่าสรุปของ **ประชากร** (มักไม่ทราบค่าจริง) | เวลาตอบสนองเฉลี่ยของทุกคำขอ (สัญลักษณ์ μ) |
| ค่าสถิติ (Statistic) | ค่าสรุปที่คำนวณจาก **ตัวอย่าง** | เวลาเฉลี่ยของ 20 รายการ (สัญลักษณ์ x̄) |

หลักจำง่าย ๆ คือ **พารามิเตอร์ = ประชากร, สถิติ = ตัวอย่าง** (P กับ P, S กับ S)

### 3.2 ความลำเอียงในการเก็บข้อมูล (Sampling Bias)

ความลำเอียงเกิดเมื่อวิธีเก็บข้อมูลทำให้ตัวอย่างไม่เป็นตัวแทนของประชากร ตัวอย่างเช่น ถ้าเก็บ log เฉพาะช่วงตี 3 ซึ่งระบบว่าง เวลาตอบสนองจะต่ำกว่าความเป็นจริงของทั้งวัน ต่อให้เก็บได้ 1 ล้านรายการก็ยังลำเอียง เพราะ **ขนาดตัวอย่างที่ใหญ่ไม่ช่วยแก้ความลำเอียงจากวิธีเก็บ**

> **กล่องเตือน** ก่อนคำนวณสถิติใด ๆ ให้ถามเสมอว่า "ข้อมูลนี้เก็บมาอย่างไร เก็บช่วงไหน และขาดกลุ่มใดไปหรือไม่"

### 3.3 ชนิดของข้อมูล

```
ข้อมูล (Data)
├── จัดประเภท (Categorical)
│    ├── นามบัญญัติ (Nominal)  : ไม่มีลำดับ เช่น สถานะ HTTP, ชื่อ endpoint, ระบบปฏิบัติการ
│    └── อันดับ (Ordinal)      : มีลำดับ เช่น ระดับความรุนแรง Low/Medium/High, คะแนนความพึงพอใจ 1–5
└── เชิงปริมาณ (Quantitative)
     ├── ไม่ต่อเนื่อง (Discrete)  : นับได้ เช่น จำนวนคำขอต่อนาที, จำนวน error
     └── ต่อเนื่อง (Continuous)   : วัดได้ละเอียด เช่น เวลาตอบสนอง (ms), อุณหภูมิ CPU
```

| ตัวแปรใน RegisRERU | ชนิด | เหตุผล | สถิติที่เหมาะ |
|---|---|---|---|
| สถานะ HTTP (200/404/500) | จัดประเภท (นามบัญญัติ) | เป็นรหัส ไม่ได้บอกปริมาณ บวกลบกันไม่มีความหมาย | ความถี่ สัดส่วน ฐานนิยม |
| ระดับความรุนแรง (Low/Med/High) | จัดประเภท (อันดับ) | เรียงลำดับได้ แต่ระยะห่างไม่เท่ากัน | ความถี่ มัธยฐานของอันดับ |
| จำนวนคำขอต่อนาที | เชิงปริมาณ (ไม่ต่อเนื่อง) | นับเป็นจำนวนเต็ม | ค่าเฉลี่ย SD |
| เวลาตอบสนอง (ms) | เชิงปริมาณ (ต่อเนื่อง) | วัดได้ละเอียด มีหน่วย | ค่าเฉลี่ย มัธยฐาน SD IQR ฮิสโตแกรม |

> **ข้อผิดพลาดที่พบบ่อย** รหัสนักศึกษาหรือรหัสสถานะ 404 เป็นตัวเลข แต่ไม่ใช่ข้อมูลเชิงปริมาณ เพราะการหาค่าเฉลี่ยของรหัสสถานะไม่มีความหมายทางสถิติ

## ส่วนที่ 4: สถิติสรุปค่ากลางและการกระจาย

### 4.1 ค่ากลาง (Measures of Center)

**ค่าเฉลี่ย (Mean)** เท่ากับผลรวมของข้อมูลหารด้วยจำนวนข้อมูล

x̄ = (x₁ + x₂ + … + xₙ) / n

**มัธยฐาน (Median)** คือค่ากลางเมื่อเรียงข้อมูลจากน้อยไปมาก ถ้า n เป็นคี่ ใช้ค่าตรงกลาง ถ้า n เป็นคู่ ใช้ค่าเฉลี่ยของสองค่ากลาง

**ฐานนิยม (Mode)** คือค่าที่พบบ่อยที่สุด ใช้กับข้อมูลจัดประเภทได้ดี

### ตัวอย่างพร้อมวิธีคิด 4.1 — ค่าสูงเพียงค่าเดียวดึงค่าเฉลี่ย

เวลาตอบสนอง 5 คำขอ: 100, 110, 120, 130, 540 ms

- ค่าเฉลี่ย = (100 + 110 + 120 + 130 + 540) / 5 = 1,000 / 5 = **200 ms**
- มัธยฐาน = ค่ากลางลำดับที่ 3 = **120 ms**

สังเกตว่า 4 ใน 5 คำขอเร็วกว่า 131 ms แต่ค่าเฉลี่ยบอก 200 ms ซึ่งไม่ตรงกับประสบการณ์ของผู้ใช้ส่วนใหญ่ ค่าเฉลี่ยจึงไวต่อค่าสุดโต่ง ส่วนมัธยฐานทนทานกว่า (robust) ตารางต่อไปนี้สรุปเปรียบเทียบ

| คุณสมบัติ | ค่าเฉลี่ย | มัธยฐาน |
|---|---|---|
| ใช้ข้อมูลทุกค่าในการคำนวณ | ใช่ | ไม่ (ใช้ตำแหน่ง) |
| ไวต่อค่าสุดโต่ง | มาก | น้อย |
| เหมาะกับการกระจายเบ้ขวา (เช่น เวลาตอบสนอง) | ไม่ค่อยเหมาะ | เหมาะ |
| นำไปใช้ต่อในการอนุมานเชิงสถิติ | ใช้บ่อยมาก | ใช้น้อยกว่า |

### 4.2 การกระจาย (Measures of Spread)

ค่ากลางอย่างเดียวไม่พอ ระบบสองระบบอาจมีค่าเฉลี่ย 120 ms เท่ากัน แต่ระบบหนึ่งตอบ 118–122 ms สม่ำเสมอ อีกระบบตอบตั้งแต่ 20 ถึง 500 ms ผู้ใช้จะรู้สึกต่างกันมาก

**พิสัย (Range)** = ค่าสูงสุด − ค่าต่ำสุด ง่ายแต่ไวต่อค่าสุดโต่งมาก

**ความแปรปรวนและส่วนเบี่ยงเบนมาตรฐาน (Variance / SD)**

- SD ของตัวอย่าง: s = √[ Σ(xᵢ − x̄)² / (n − 1) ]

เหตุผลที่หารด้วย **n − 1** (องศาอิสระ) คือเมื่อเราใช้ x̄ แทน μ ซึ่งเป็นค่าที่ "พอดีที่สุด" กับตัวอย่างอยู่แล้ว ผลรวมกำลังสองจะน้อยกว่าความจริงเล็กน้อย การหารด้วย n − 1 ช่วยชดเชยให้ประมาณความแปรปรวนของประชากรได้ไม่ต่ำเกินไป

> **ข้อควรระวังเรื่อง pandas และ NumPy** `Series.std()` ของ pandas ใช้ n − 1 เป็นค่าเริ่มต้น (`ddof=1`) แต่ `np.std()` ใช้ n เป็นค่าเริ่มต้น (`ddof=0`) ต้องระบุ `ddof=1` เมื่อใช้ NumPy กับข้อมูลตัวอย่าง

### ตัวอย่างพร้อมวิธีคิด 4.2 — คำนวณ SD ด้วยมือ

ข้อมูล: 5, 7, 8, 10, 15

1. หาค่าเฉลี่ย x̄ = (5+7+8+10+15)/5 = 45/5 = 9
2. หาผลต่างจากค่าเฉลี่ย: −4, −2, −1, 1, 6
3. ยกกำลังสอง: 16, 4, 1, 1, 36 รวมได้ 58
4. s² = 58 / (5 − 1) = 14.5
5. s = √14.5 ≈ **3.81**

(ถ้าเป็นประชากรทั้งหมด จะหารด้วย 5 ได้ σ² = 11.6, σ ≈ 3.41)

### 4.3 ควอร์ไทล์และ IQR

ควอร์ไทล์แบ่งข้อมูลที่เรียงแล้วเป็น 4 ส่วนเท่า ๆ กัน Q1 คือตำแหน่ง 25% Q2 คือมัธยฐาน (50%) Q3 คือตำแหน่ง 75%

**IQR = Q3 − Q1** วัดความกว้างของข้อมูลช่วงกลาง 50% จึงทนต่อค่าสุดโต่ง

> **หมายเหตุวิธีคำนวณ** ตำราแต่ละเล่มและซอฟต์แวร์แต่ละตัวมีวิธีหาควอร์ไทล์ต่างกันเล็กน้อย ในรายวิชานี้ใช้ค่าจาก `pandas.Series.quantile()` ซึ่งใช้การประมาณค่าเชิงเส้นระหว่างตำแหน่ง (linear interpolation) ให้ระบุเสมอว่าใช้วิธีใด

### 4.4 เกณฑ์ตรวจค่าผิดปกติด้วย IQR (Tukey's Fences)

- รั้วล่าง (lower fence) = Q1 − 1.5 × IQR
- รั้วบน (upper fence) = Q3 + 1.5 × IQR

ค่าที่อยู่นอกรั้วถูกทำเครื่องหมายว่า "ควรตรวจสอบ" (potential outlier) ไม่ได้แปลว่า "ต้องลบทิ้ง" การตัดสินใจขึ้นกับสาเหตุของค่านั้น

## ส่วนที่ 5: การแสดงข้อมูลด้วยกราฟ

### 5.1 ฮิสโตแกรม (Histogram)

ฮิสโตแกรมแบ่งช่วงค่าเป็นช่วง (bin) ที่กว้างเท่ากัน แล้วนับจำนวนข้อมูลในแต่ละช่วง แท่งกราฟที่ติดกันแสดงว่าตัวแปรเป็นแบบต่อเนื่อง

**องค์ประกอบที่ต้องมีทุกครั้ง:** ชื่อกราฟ ชื่อแกน X พร้อมหน่วย (ms) ชื่อแกน Y (จำนวนคำขอ) และจำนวนช่วง

### 5.2 รูปร่างของการกระจาย

```
สมมาตร            เบ้ขวา (Right-skewed)      เบ้ซ้าย (Left-skewed)
   ▂▅█▅▂             █▆▃▂▁▁                    ▁▁▂▃▆█
 mean = median     mean > median               mean < median
```

### 6.1 ภาพรวมขั้นตอน

```
① ตรวจข้อมูลดิบ → ② สร้าง Series → ③ คำนวณสถิติสรุป → ④ วาดกราฟ
        → ⑤ ตรวจค่าผิดปกติ → ⑥ ทดลองตัดค่า (เก็บชุดเต็มไว้) → ⑦ เขียนสรุป
```

### 6.2 ขั้นที่ 1–3: สร้าง Series และคำนวณสถิติ

```python
import pandas as pd

data = [101, 104, 108, 109, 110, 113, 114, 118, 120, 123,
        124, 125, 130, 132, 138, 142, 149, 158, 174, 420]

s = pd.Series(data, name="response_ms")

n      = s.count()
mean   = s.mean()
median = s.median()
sd     = s.std(ddof=1)        # SD ของตัวอย่าง (หารด้วย n-1)
q1     = s.quantile(0.25)
q3     = s.quantile(0.75)
iqr    = q3 - q1

print(f"n      = {n}")
print(f"mean   = {mean:.2f} ms")
print(f"median = {median:.2f} ms")
print(f"SD     = {sd:.2f} ms")
print(f"Q1     = {q1:.2f} ms, Q3 = {q3:.2f} ms, IQR = {iqr:.2f} ms")
```

**ผลลัพธ์ที่คาดหวัง**

| สถิติ | ค่า |
|---|---|
| n | 20 |
| ค่าเฉลี่ย | 140.60 ms |
| มัธยฐาน | 123.50 ms |
| SD ของตัวอย่าง | 68.40 ms |
| Q1 | 112.25 ms |
| Q3 | 139.00 ms |
| IQR | 26.75 ms |

สังเกตว่าค่าเฉลี่ย (140.60) สูงกว่ามัธยฐาน (123.50) ประมาณ 17 ms และ SD (68.40) สูงมากเมื่อเทียบกับ IQR (26.75) เป็นสัญญาณแรกว่ามีค่าสุดโต่ง

> ทางลัด: `s.describe()` แสดง count, mean, std, min, 25%, 50%, 75%, max ในคำสั่งเดียว

### 6.4 ขั้นที่ 5: ตรวจค่าผิดปกติ

```python
lower = q1 - 1.5 * iqr
upper = q3 + 1.5 * iqr
print(f"รั้วล่าง = {lower:.3f}, รั้วบน = {upper:.3f}")
print("ค่านอกรั้ว:", s[(s < lower) | (s > upper)].tolist())
```

คำนวณได้ รั้วล่าง = 112.25 − 1.5(26.75) = 72.125 และ รั้วบน = 139.00 + 1.5(26.75) = **179.125** ค่านอกรั้วมีเพียง **420 ms** (ส่วน 174 ms ยังอยู่ในรั้ว)

> **แนวตอบ:** x̄ = 40/5 = 8; ผลต่างกำลังสอง = 16+4+0+4+16 = 40; s² = 40/4 = 10; s = √10 ≈ 3.16

> **แนวตอบ:** เพราะใช้ x̄ แทน μ ทำให้ผลรวมกำลังสองต่ำกว่าจริง การหารด้วย n − 1 ช่วยแก้ความเอนเอียง `np.std` ใช้ ddof=0 (หารด้วย n) เป็นค่าเริ่มต้น ส่วน pandas ใช้ ddof=1 จึงได้ค่าไม่เท่ากัน (ของ NumPy น้อยกว่าเล็กน้อย)
